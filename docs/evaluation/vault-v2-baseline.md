## Disposable migration inventory

`tests/fixtures/vault-v2/manifest-cases.json` is a frozen, wholly synthetic, disposable eight-file tree. Each `base64` value is the authoritative raw file content; `bytes` and `sha256` cover those bytes, not decoded/normalized Markdown. Five V1 revision files were rendered with the existing `renderRevision`/`encodeRevision` codecs and pass `decodeRevision`. The case includes a root revision and two divergent children of the same logical note (both logical heads, unresolved conflict), a separately approved active preference whose approval fingerprint matches the real `payloadHash` and passes the V1 approval logic with provenance, a Unicode-titled note with human-authored section, an unadopted human note with mixed line endings, a binary attachment, and `.obsidian` settings. `logical_heads` records the identities and explicitly leaves the fork unresolved. The test materializes the corpus only in `vaultSandbox()`, verifies every raw hash and parent hash, decodes every revision, and compares the complete tree to `inventoryTree`; it never touches a live vault. Inventory includes `.obsidian` and attachments even though ordinary retrieval may exclude them.

`inventoryTree(root)` reads bytes only, rejects symbolic links (including a file symlink, a symlinked ancestor of the supplied root, directory links, and a root that is itself a symlink), rejects special files, and sorts relative slash paths by code-unit order. Containment uses pinned directory descriptors rather than pathname re-checks: the root is acquired from a trusted `/` by opening each absolute-path component relative to the previous descriptor with `O_RDONLY | O_DIRECTORY | O_NOFOLLOW`; directories are enumerated through `/proc/self/fd/<descriptor>` and each child is opened as `/proc/self/fd/<descriptor>/<single-entry-name>`; leaves are opened with `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` and must `fstat` as regular files before reading. Replacing a source pathname or ancestor with a symlink cannot redirect later access to the symlink target, and the root identity is the acquired directory object, not its later pathname; this is not a claim that the root stays permanently at its original pathname. Identity/change checks are mutation detection, not containment proof, and concurrent mutation can fail the inventory because the result is not an atomic snapshot. If `/proc/self/fd` is unavailable or unusable the inventory fails closed, closes every descriptor on every path, and never falls back to a pathname walker. Production migration still requires all writers stopped and hash-verified backups.
